# 구현 계획

## 구조
| 파일 | 역할 |
|---|---|
| `logic.py` | 화면·DB와 무관한 규칙(지원 검사, 투표 처리, 마감, 배정 검사 5가지, 모든 경우를 따지는 배정, AI 답 읽기, CSV 읽기). 컴퓨터에서 바로 테스트 가능 |
| `db.py` | 연결 풀, 트랜잭션 락, DB 읽기/쓰기, bcrypt 로그인 |
| `ai.py` | 오픈라우터 호출. 별도 스레드 + 시계로 모델마다 120초 전체 대기 시간 제한 |
| `streamlit_app.py` | 화면과 key |
| `schema.sql` | tf_ 테이블(앱 시작 때 그대로 실행됨) |
| `tests/test_logic.py` | 부록 시나리오 3개와 규칙 테스트 |

## 단계
1. **규칙 먼저**: `logic.py`와 테스트로 부록 시나리오 3개를 DB 없이 통과시킨다.
2. **DB**: `schema.sql` → Supabase(6장 프로젝트 재사용, 새 프로젝트 만들지 않음) → `db.py`.
3. **화면**: 로그인 → 학생 화면(지원·투표) → 관리자 화면(명단·마감).
4. **AI 배정**: 모델 3개 순서 호출 → 검사 5가지 → 실패하면 앱이 직접 배정.
5. **배포**: 비공개 저장소 → Streamlit Community Cloud(Secrets) → 공개 설정 → 시크릿 창에서 로그인 화면 확인.
6. **마무리**: 부록 시나리오 직접 실행, README 사례 기록, DB 일시정지 방지, zip.

## 어려운 해결을 고른 기능
| 기능 | 선택 | 방법 |
|---|---|---|
| 다른 사람의 변경 보기 | 어려운 해결 | 학생 화면 `st.fragment(run_every=3)` (관리자 화면은 새로 고침 단추) |
| 필수 포함 역할을 지킬 수 없는 팀 | 어려운 해결 | `join_problem`의 자리 계산 |
| 같은 팀에 대기 중인 지원이 여럿 | 어려운 해결 | 승인 직전 `join_problem` 재검사 |
| 마지막 자리에 두 명이 동시에 | 어려운 해결 | `tf_members` 유일성 제약 + 트랜잭션 락 |
| AI 응답이 늦을 때 | 어려운 해결 | 모델마다 120초 전체 대기 시간 |
| 3차 모델까지 실패 | 어려운 해결 | `solve_assignment`(모든 경우를 따짐) |
| AI 대기 중 화면 | 어려운 해결 | 몇 차 모델, 경과 초 표시 |
| DB 일시정지 방지 | 어려운 해결 | GitHub Actions 매일 질의 |

## 테스트 계획
- 자동: `python -m unittest discover -s tests -v`
- 수동: 배포한 앱에서 부록 1~3의 단계를 위에서부터 실행하고 결과 안내 첫 단어를 기대 결과와 비교. 학생 계정(비밀번호 1234)과 관리자로 번갈아 로그인.
- 보안: 학생 계정으로 관리자 화면 접근 불가, 틀린 비밀번호 거부, 화면·저장소에 키 없음 확인.
