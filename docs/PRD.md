# PRD: 팀 프로젝트 팀 편성 웹 앱

## 1. 목적
학생들이 팀 프로젝트를 위한 팀을 스스로 편성하는 웹 앱을 만든다. 마감 때까지 팀에 들어가지 못한 학생은 AI가 배정을 돕고, 앱이 AI의 답을 규칙으로 검사한다.

## 2. 사용자
| 사용자 | 하는 일 |
|---|---|
| 학생(가상 학생) | 학번과 비밀번호로 로그인, 팀 목록과 팀원의 주·보조 역할 보기, 팀에 지원, 내 팀에 들어온 지원에 찬성·거부 |
| 관리자(학번 admin) | 명단 CSV와 팀 수로 처음 상태 만들기, 모집 마감, 남은 학생의 AI 배정안 확인과 확정 |

## 3. 규칙 (공고 2장)
- 역할 6개: 기획자, 웹 프로그래머, 프론트엔드 디자이너, 테스터, 보고서 작성자, 발표자. 학생마다 주 역할 1개, 보조 역할 0~2개.
- 확정한 팀: 2~4명, 주 역할 중복 없음, 기획자와 웹 프로그래머를 맡을 수 있는 학생이 서로 다른 사람으로 1명씩(주·보조 역할 모두 인정).
- 빈 팀에 지원하면 바로 승인. 팀원이 있는 팀은 그 시점의 팀원 전원이 찬성해야 승인, 한 명이라도 거부하면 즉시 거절.
- 승인 직전에 규칙(정원, 주 역할 중복, 필수 포함 역할 자리)을 다시 검사하고, 어기면 거절.
- 한 학생은 결과가 나오기 전에는 다른 팀에 지원할 수 없고, 이미 팀이 있으면 지원할 수 없다. 투표는 바꿀 수 없다.
- 마감: 대기 지원은 거절, 1명뿐인 팀의 학생은 팀에서 빠짐. 이후 AI 배정 → 검사 → 관리자 확정.

## 4. 기능 요구사항
| 번호 | 기능 | 완료 기준 |
|---|---|---|
| F1 | 로그인 | 학번+비밀번호(bcrypt 해시), 틀리면 로그인 안 됨, 학생은 관리자 기능 사용 불가 |
| F2 | 명단 올리기 | BOM 있는 UTF-8 CSV와 팀 수로 상태 초기화, 관리자 계정은 남김 |
| F3 | 지원 | 결과 안내가 승인/대기/막힘으로 시작하고 이유 표시 |
| F4 | 투표 | 찬성/거부, 한 번 투표하면 단추 대신 "내 투표: 찬성" 표시 |
| F5 | 필수 포함 역할 자리 지키기(어려운 해결) | 지원자가 들어간 뒤 남는 자리 < 못 채운 필수 포함 역할 수 → 막힘 |
| F6 | 승인 직전 재검사(어려운 해결) | 처리 순서는 투표가 끝난 순서 |
| F7 | 마감 | 대기 지원 거절, 1명 팀 해체, 팀이 없는 학생 표시 |
| F8 | AI 배정 | 모델 3개 순서대로, 모델마다 120초 전체 대기 시간 제한, 검사 5가지, 진행 안내(몇 차 모델인지) |
| F9 | 3차까지 실패(어려운 해결) | 앱이 모든 경우를 따져 규칙을 지키는 배정을 찾음. 없으면 "규칙을 지키는 배정이 없음"과 이유 |
| F10 | 확정 | 현재 상태로 다시 검사한 뒤 DB에 저장 |
| F11 | 다른 사람의 변경 보기(어려운 해결) | st.fragment로 학생 화면을 3초마다 자동 갱신 |

## 5. 비기능 요구사항
- 키, DB 주소, 관리자 비밀번호는 `.env`/Streamlit Secrets에만 둔다. 코드·깃허브·화면에 출력하지 않는다.
- DB 연결은 연결 풀로 한 번 만들고 다시 쓴다. 화면 한 번에 질의 한 번.
- 두 사람이 동시에 눌러도 순서대로 처리(트랜잭션 락)하고, DB 유일성 제약이 마지막 안전장치.
- DB 일시정지 방지: 마감 날 앱 사용 + GitHub Actions로 매일 DB 질의.
- 화면 요소의 key는 공고 2.7절 표를 그대로 사용.

## 6. 데이터 (schema.sql)
tf_students, tf_student_sub_roles, tf_teams, tf_members, tf_applications, tf_votes, tf_settings, tf_ai_logs.
`tf_members`의 `(team_id, slot_no)` 기본 키와 `student_id` unique가 "마지막 자리에 두 명이 동시에 들어감"과 "한 학생은 한 팀"을 DB에서 지킨다.

## 7. 성공 기준
- 부록의 연습용 시나리오 3개를 처음부터 끝까지 실행했을 때 모든 단계의 결과 안내가 기대 결과와 같다.
- 확정한 팀 구성이 모든 규칙을 지킨다.
- 연습용 시나리오의 이름·순서에 맞춰 결과를 정해 두지 않는다(규칙만 구현).
